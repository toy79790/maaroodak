# SECURITY — معروضك

نموذج التهديد والضوابط المطبَّقة. المنصة تتعامل مع بيانات شخصية حساسة (أسماء، أرقام هوية، جوال، ظروف مالية وصحية) — لذلك الأمان ليس طبقة إضافية.

---

## 1. نموذج التهديد

| # | التهديد | الأثر | الضابط |
|---|---|---|---|
| T1 | سرقة جلسة (XSS / سرقة كوكي) | انتحال كامل | كوكي `httpOnly`+`Secure`+`SameSite=Lax` · CSP · تخزين **hash** الجلسة |
| T2 | وصول أفقي (IDOR) — قراءة معروض غيرك | تسريب بيانات شخصية | كل استعلام مقيّد بـ `userId` **في شرط الاستعلام نفسه** لا بعد الجلب |
| T3 | تصعيد صلاحية إلى Admin | سيطرة كاملة | RBAC على مستوى الـ Handler لا الـ Layout · الدور من DB لا من الـ JWT |
| T4 | حقن أوامر في الـ Prompt | مخرجات ضارة / تجاوز الضوابط | تغليف `<user_facts>` + تهريب + حدود طول (`AI_SYSTEM.md §9`) |
| T5 | تسريب مفتاح الـ AI | تكلفة مالية مباشرة | المفتاح على الخادم فقط · لا `NEXT_PUBLIC_` · لا يُعاد في أي استجابة |
| T6 | إساءة استخدام الـ AI (استنزاف) | تكلفة | Rate limit + Credits + Quota |
| T7 | CSRF على العمليات المُغيِّرة | حذف/تعديل بلا علم | `SameSite=Lax` + رمز CSRF مزدوج + فحص `Origin` |
| T8 | XSS مخزَّن عبر محتوى المعروض | سرقة جلسات | تعقيم HTML عند الحفظ **وعند العرض** |
| T9 | حشو بيانات الاعتماد | اختراق حسابات | Rate limit على الدخول + Argon2/bcrypt + رسائل موحّدة |
| T10 | تعداد الحسابات | خصوصية | رد موحّد في التسجيل واستعادة كلمة المرور |
| T11 | تسرّب بين المستأجرين | كارثي | فرض `organizationId` في طبقة Repository |
| T12 | رفع ملف خبيث | تنفيذ / تخزين | نوع + حجم + إعادة تسمية + تخزين خارج جذر الويب |
| T13 | كشف تفاصيل داخلية في الأخطاء | استطلاع | رسائل عامة + تسجيل داخلي فقط |
| T14 | SQL Injection | كارثي | Prisma (استعلامات مُعامَلة) · `$queryRaw` بمعاملات فقط |

## 2. المصادقة

**الاختيار:** جلسات موقّعة بذاتها (JWT عبر `jose`) **مع سجل جلسات في القاعدة** — لا JWT عديم الحالة بالكامل.
السبب: نحتاج **الإبطال الفوري** (تسجيل خروج من كل الأجهزة، تعطيل حساب، تغيير كلمة مرور).

```
تسجيل الدخول
  → التحقق من كلمة المرور (bcrypt, cost=12)
  → إنشاء رمز عشوائي 32 بايت
  → تخزين SHA-256(token) في Session (لا الرمز نفسه)
  → JWT يحمل { sid, uid } موقّعاً بـ HS256 في كوكي httpOnly
كل طلب محمي
  → فك JWT (سريع)
  → جلب Session بـ sid والتحقق: غير منتهية، غير مُبطلة، المستخدم نشط
  → الدور يُقرأ من DB — لا يُوثق بالدور المضمّن في الرمز
```

| الضابط | القيمة |
|---|---|
| كلمة المرور | ≥ 8 أحرف، ليست من قائمة الشائعة، bcrypt cost 12 |
| عمر الجلسة | 7 أيام · تجديد منزلق عند نشاط بعد 24 ساعة |
| تغيير كلمة المرور | يُبطل **كل** الجلسات الأخرى |
| رمز استعادة كلمة المرور | 32 بايت عشوائي · SHA-256 مخزّن · 30 دقيقة · استخدام واحد |
| رد الاستعادة | موحّد دائماً: «إن كان البريد مسجلاً فستصلك رسالة» |
| رد التسجيل بإيميل موجود | موحّد — لا يكشف الوجود |

**الكوكي:** `httpOnly` · `secure` (إنتاج) · `sameSite=lax` · `path=/` · بلا `domain` عريض.

## 3. التخويل (RBAC)

```ts
const PERMISSIONS = {
  USER:        ['letter:own:*', 'interview:own:*', 'profile:own:*', 'favorite:own:*'],
  ADMIN:       [...USER, 'department:*', 'question:*', 'template:*', 'prompt:*',
                'user:read', 'letter:read', 'analytics:read'],
  SUPER_ADMIN: ['*'],
} as const;
```

**قواعد الفرض:**
1. `requireUser()` / `requireRole()` في **كل** Route Handler و Server Action — لا اعتماد على الـ Layout وحده.
2. `middleware.ts` فحص وجود كوكي فقط (Edge، بلا DB) — **ليس** حارس أمان.
3. ملكية المورد تُفحص **داخل الاستعلام**:
   ```ts
   // ✅ صحيح
   prisma.letter.findFirst({ where: { id, userId: ctx.userId, deletedAt: null } })
   // ❌ خطأ — IDOR
   const l = await prisma.letter.findUnique({ where: { id } }); if (l.userId !== ctx.userId) …
   ```
4. مسارات `/api/admin/*` تسجّل كل عملية في `AuditLog`.

## 4. التحقق من المدخلات

- **Zod على كل حدّ** — كل Body و Query و Params. لا `any`، لا ثقة بالعميل.
- إجابات الأسئلة تُتحقق بمخطط **مُولَّد ديناميكياً** من تعريف السؤال (النوع + `validation`).
- حدود: نص 500 · نص طويل 2000 · رقم `[-1e12, 1e12]` · تاريخ نطاق معقول · ملف 5MB.
- تطبيع: البريد lowercase+trim · الجوال أرقام لاتينية · إزالة المحارف الضابطة والاتجاهية (`‪-‮`) من كل نص.
- **رفض** المفاتيح غير المعرّفة (`.strict()`) — يمنع تمرير حقول غير متوقعة.

## 5. تحديد المعدّل (Rate Limiting)

نافذة منزلقة داخل الذاكرة للتطوير، وواجهة `RateLimiterPort` تسمح باستبدالها بـ Redis في الإنتاج.

| المسار | الحد | المفتاح |
|---|---|---|
| `POST /api/auth/login` | 5 / 15 دقيقة | IP + البريد |
| `POST /api/auth/register` | 3 / ساعة | IP |
| `POST /api/auth/forgot-password` | 3 / ساعة | IP + البريد |
| `POST /api/letters/generate` | 5 / 10 دقائق | userId |
| `POST /api/letters/:id/ai-tool` | 20 / 10 دقائق | userId |
| `POST /api/interview/*/follow-up` | 10 / 10 دقائق | userId |
| باقي `/api/*` | 100 / دقيقة | userId ∥ IP |

الاستجابة `429` مع `Retry-After`. الحدود قابلة للضبط من `SystemSetting`.

## 6. CSRF و CORS

- كل الكوكيز `SameSite=Lax` → يحجب طلبات POST عبر المواقع افتراضياً.
- فحص `Origin` على كل طلب مُغيِّر (`POST/PUT/PATCH/DELETE`) في
  `lib/security/cors.ts` — الأصول المسموح بها تأتي من `NEXT_PUBLIC_APP_URL`
  و`ALLOWED_ORIGINS`، لا من الشيفرة.
- الرفض يُسجَّل كحدث أمني (`scope: security`).
- Server Actions محمية أصلاً بآلية Next.js، والفحص أعلاه طبقة ثانية.

**CORS:** التطبيق أحادي الأصل — Next.js يقدّم الواجهة والـ API معاً — فلا
حاجة إلى CORS أصلاً. الترويسات تُصدر فقط لأصل مصرّح به صراحةً، مع
`Vary: Origin` (بدونه تُخزّن الوسائط ترويسة أصل واحد وتُعيدها لغيره).

> ⚠️ `Access-Control-Allow-Origin: *` **غير مستخدم إطلاقاً**. مع الكوكيز
> يمنعه المتصفح أصلاً، ووجوده يوهم بأن الوصول مفتوح فيُبنى عليه لاحقاً.

**غياب `Origin` مقبول:** بعض العملاء غير المتصفحية لا يرسلونه، والمتصفح
يرسله دائماً في الطلبات عبر المواقع — فالغياب ليس هجوم CSRF.

## 7. XSS ومحتوى المعروض

محتوى المعروض HTML (من المحرر) → أخطر سطح في التطبيق.

1. **تعقيم عند الحفظ**: قائمة سماح صارمة — `p, br, strong, em, u, h1-h3, ul, ol, li, blockquote, span[style=text-align]` فقط.
   يُحذف كل ما عداها، وكل سمة `on*`، وكل `href` غير `http(s)`.
2. **تعقيم عند العرض** أيضاً (دفاع عميق) — لا نثق بما في القاعدة.
3. لا `dangerouslySetInnerHTML` إلا على مخرج المعقِّم، في مكوّن واحد `<SafeHtml>`.
4. **CSP** (في `next.config.ts`):
   ```
   default-src 'self';
   script-src 'self' 'nonce-<random>';
   style-src 'self' 'unsafe-inline';
   img-src 'self' data: blob:;
   font-src 'self' data:;
   connect-src 'self';
   frame-ancestors 'none';
   base-uri 'self';
   form-action 'self';
   object-src 'none';
   ```

## 9. الأسرار وبيئة التشغيل

المرجع الكامل: [ENVIRONMENT.md](ENVIRONMENT.md).

- `config/env.ts` يتحقق من كل المتغيرات بـ Zod **عند الإقلاع** — الفشل مبكر وواضح.
- `ANTHROPIC_API_KEY` · `SESSION_SECRET` (≥32 حرف) · `DATABASE_URL` · مفاتيح
  التخزين — لا يُستورد أي منها في ملف عميل (`server-only` يفرض ذلك).
- **لا `NEXT_PUBLIC_` لأي سر.** `NEXT_PUBLIC_*` تُدمج في حزمة المتصفح وقت
  البناء ويقرؤها أي زائر. فحص في CI يرفض أي اسم يحتوي
  `KEY|SECRET|TOKEN|PASSWORD|CREDENTIAL`.
- `.env*` في `.gitignore`؛ `.env.example` بقيم وهمية فقط. فحص في CI يرفض
  دفع `.env`.
- **سرّ منفصل لكل بيئة.** تسريب سرّ staging يجب ألّا يمنح جلسة إنتاج واحدة.

### فحوص الإقلاع في الإنتاج

عند `APP_ENV=production` يرفض التطبيق العمل إن كان:

| الفحص | السبب |
|---|---|
| `SESSION_SECRET` هو القيمة الافتراضية | سرّ معروف = انتحال أي جلسة |
| `NEXT_PUBLIC_APP_URL` بلا HTTPS | كوكيز الجلسة تمرّ مكشوفة |
| `NEXT_PUBLIC_APP_URL` على localhost | إعداد لم يُبدَّل بعد النسخ |
| `DATABASE_URL` على localhost | تحذير — قاعدة تطوير في الإنتاج |
| `STORAGE_DRIVER=s3` بلا بيانات اعتماد | يفشل عند أول رفع لا عند الإقلاع |
| `STORAGE_DRIVER=local` في بيئة منشورة | فقدان ملفات المستخدمين بصمت |

للتحقق قبل النشر:

```bash
npm run check:env
```

يشغّل نفس التحقق على سيناريوهات إعداد سليمة وفاسدة ويطبع النتيجة.

## 10. الملفات المرفوعة

**الحالة اليوم:** v1 لا ترفع أي ملف. المعاريض تُصدَّر بالبثّ المباشر (PDF عبر
طباعة المتصفح، DOCX يُبنى في الذاكرة) ولا تُكتب على القرص إطلاقاً.

الضوابط أدناه مطبّقة في `services/storage/ports.ts` وجاهزة عند تفعيل المرفقات:

- الأنواع: `pdf · jpeg · png · webp` — يُتحقق بـ**الرقم السحري** لا بالامتداد
  ولا بـ `Content-Type`؛ كلاهما يتحكم فيه العميل ورفع ملف تنفيذي باسم
  `.pdf` أمر تافه.
- الحد 5MB للملف.
- **المفتاح عشوائي ولا يُشتق من اسم الملف الأصلي**: اسم مثل
  «تقرير-طبي-محمد.pdf» يسرّب معلومة شخصية في الرابط نفسه، والاسم المخمَّن
  يجعل الملف قابلاً للوصول بلا تخويل.
- الملفات **خاصة افتراضياً**؛ الوصول برابط موقّت قصير الأجل.
- `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`.
- **لا تُرسل محتويات الملفات إلى الـ AI** — تُذكر أسماؤها كمرفقات فقط.

**لا كتابة في نظام ملفات الخادم في الإنتاج.** الحاويات لها نظام ملفات مؤقت
وغير مشترك؛ `getStorage()` يرفض التخزين المحلي في البيئات المنشورة **عند
الإقلاع** — الفشل المبكر أرحم من فقدان ملفات بصمت.

## 11. الخصوصية

- **تقليل الجمع**: لا نطلب رقم الهوية إلا حين يتطلبه القالب فعلاً.
- **حذف الحساب**: حذف فعلي لكل بيانات المستخدم (Cascade) عدا `AIUsage` (يُفصل بـ `SetNull` للمحاسبة).
- **تصدير البيانات**: نقطة `GET /api/account/export` تُرجع JSON بكل بيانات المستخدم.
- **السجلات**: التعقيم إلزامي في `lib/logging/logger.ts` — تُحجب كلمات المرور
  والرموز والمفاتيح وأرقام الهوية و IBAN ومحتوى المعاريض وإجابات المستخدمين،
  **بالاسم** لا اعتماداً على انتباه كاتب السطر. الحجب يشمل التداخل والمصفوفات.
  `AIUsage` يخزّن **عدّادات فقط** — لا نص الـ Prompt ولا المخرَج.
- الاحتفاظ: `AnalyticsEvent` 12 شهراً · `AuditLog` 24 شهراً · الجلسات المنتهية تُنظَّف يومياً.

- [ ] `APP_ENV=production` و`secure` مفعّل على الكوكيز

- [ ] `npm run check:env` يمرّ
- [ ] مفتاح الذكاء الاصطناعي لا يظهر في حزمة المتصفح
- [ ] Rate limiting مدعوم بـ Redis (لا ذاكرة العملية) — انظر أدناه
- [ ] حساب Admin الافتراضي غير موجود (البذور تتخطّاه في الإنتاج)
- [ ] نسخ احتياطي يومي للقاعدة + **اختبار استرجاع فعلي**
- [ ] `npm audit --audit-level=high` نظيف
- [ ] اختبار عزل المستأجرين ناجح

### ⚠️ ثغرة معروفة في النشر متعدد النسخ

`InMemoryRateLimiter` يحفظ العدّادات في ذاكرة العملية. مع أكثر من نسخة يصبح
الحد **لكل نسخة لا لكل مستخدم**: خمس نسخ تعني خمسة أضعاف الحد الفعلي.

المخاطرة: تخمين كلمات المرور وإساءة استخدام التوليد (تكلفة مباشرة).

الحل: تنفيذ `RateLimiterPort` بـ Redis وحقنه عبر `setRateLimiter` — ملف واحد
بلا تغيير في أي نقطة استدعاء ([DECISIONS.md #D-017](DECISIONS.md)).

# TESTING — معروضك

---

## 1. الاستراتيجية

هرم اختبار مائل نحو **الوحدة**، لأن قلب المنتج (محرك الأسئلة، الشروط، القوالب، بناء الـ Prompt، الضوابط)
مكتوب كدوال نقية — أرخص وأسرع وأدق ما يمكن اختباره.

```
        ▲  E2E (Playwright) — قليلة، تغطي الرحلة الذهبية والحواجز
       ─┼─ Integration (Vitest + PostgreSQL حقيقية) — API + الصلاحيات + العزل
      ──┼── Unit (Vitest) — الخدمات النقية  ← الكتلة الأكبر
```

| الطبقة | الأداة | البيئة | الهدف |
|---|---|---|---|
| Unit | Vitest | node | الخدمات النقية |
| Component | Vitest + Testing Library | jsdom | مكوّنات المقابلة والمحرر |
| Integration | Vitest | PostgreSQL حقيقية (`maroudak_test`) | Route Handlers + Repositories |
| E2E | Playwright | خادم `next start` | الرحلة الكاملة |

**لا نستخدم قاعدة وهمية (mock) في اختبارات التكامل** — نستخدم PostgreSQL نفسها.
اختلاف السلوك بين المحاكاة والواقع هو مصدر أخطاء الإنتاج، وقاعدتنا تعمل محلياً بأمر واحد.

## 2. ما يجب اختباره (وفق طلب المشروع)

### 2.1 Question Engine — الأولوية القصوى

| الحالة | التوقّع |
|---|---|
| لا أسئلة | `isComplete = true`, `totalSteps = 0` |
| أسئلة عامة فقط | تُعرض بترتيب `order` |
| دمج النطاقات الأربعة | (dept+type) يتجاوز (type) يتجاوز (dept) يتجاوز العام |
| تعارض مفتاح `key` | يفوز **الأخص** ولا يتكرر السؤال |
| `groupKey` مشترك | السؤالان في خطوة واحدة |
| إجابة ثم رجوع | الإجابات محفوظة، `canGoBack` صحيح |
| سؤال غير نشط | لا يظهر ولا يُحتسب في `totalSteps` |
| `totalSteps` ديناميكي | يزيد عند إظهار فرع، وينقص عند إخفائه |
| `progress` | ضمن `[0,1]` دائماً ولا يتراجع بلا سبب |
| `missingRequired` | يُرجع المطلوب غير المُجاب **المرئي فقط** |

### 2.2 Conditional Logic — الأولوية القصوى

| الحالة | التوقّع |
|---|---|
| `SHOW` غير محقق | السؤال مخفي افتراضياً |
| `SHOW` محقق | يظهر |
| `HIDE` محقق | يُخفى حتى لو كان مرئياً |
| مصدر الشرط مخفي | الشرط لا يتحقق (انتشار الإخفاء) |
| سلسلة عميقة (A→B→C→D) | تُحلّ بترتيب صحيح |
| `AND` / `OR` | منطق صحيح لكل تركيبة |
| كل العوامل الـ 14 | حالة لكل عامل + قيم حدّية |
| مقارنة أرقام كنصوص | `"10" > "9"` تُعالج كأرقام لا نصوص |
| `IS_EMPTY` على `false` | `false` ليست فارغة · `""` و`[]` و`null` فارغة |
| `CHECKBOX` مع `CONTAINS` | يعمل على المصفوفة |
| دورة (A↔B) | يُكشف ويُرفض عند الحفظ |
| `REQUIRE` مشروط | السؤال يصبح مطلوباً ديناميكياً |
| **سيناريو المديونية الكامل** | «لا» ⇒ 0 أسئلة فرعية · «نعم» ⇒ 5 أسئلة · التبديل يعيد الإجابات |

### 2.3 AI Prompt Builder

| الحالة | التوقّع |
|---|---|
| اختيار الـ Prompt | (dept+type) → (type) → (dept) → افتراضي |
| الحقائق | الإجابات المخفية **لا** تُدرج |
| التغليف | كل الحقائق داخل `<user_facts>` ومهرَّبة |
| حقن أوامر | `"تجاهل التعليمات السابقة"` في إجابة → يبقى داخل الوسم ولا يُنفَّذ |
| ترتيب الطبقات | L1→L5 بالترتيب دائماً (ثبات التخزين المؤقت) |
| ثبات البادئة | نفس (dept,type) ⇒ نفس نص L1..L4 حرفياً |
| النموذج غير المدعوم | `temperature` تُحذف لنماذج Opus 5 / Sonnet 5 |

### 2.4 Guardrails

| الحالة | التوقّع |
|---|---|
| رقم غير موجود في الحقائق | `BLOCK` |
| رقم موجود بصيغة عربية-هندية (٥٠٠٠) | يُطابَق بنجاح — لا إنذار كاذب |
| السنة الحالية / التاريخ | مسموح |
| `المادة 12` | `BLOCK` |
| «أتوسل إليكم» | `WARN` |
| `{{name}}` متبقٍّ | `BLOCK` |
| `[أدخل رقم المعاملة]` | `INFO` + يُدرج في «معلومات ناقصة» |
| نص 60 كلمة / 1200 كلمة | `WARN` |

### 2.5 Template Engine

- استبدال المتغيرات · المتغير المفقود → علامة نائبة لا `undefined`
- كتل `{{#if}}` · تداخلها · عدم تنفيذ أي كود
- محاولة حقن `{{` من إجابة مستخدم → لا تُعالَج كمتغير
- `{{ai_body}}` يُستبدل بالمحتوى المُولَّد

### 2.6 Letter Generator (تكامل، مزوّد AI وهمي)

- المسار الكامل ينشئ `Letter` + `LetterVersion(v1)` + `CreditTransaction` + `AIUsage`
- فشل الـ AI ⇒ **لا** خصم ولا `Letter`
- فشل الحفظ بعد نجاح AI ⇒ `AIUsage(ORPHANED)`
- رصيد صفر ⇒ `INSUFFICIENT_CREDITS` قبل أي نداء AI
- `refusal` ⇒ `AI_BLOCKED`

### 2.7 Authentication

- تسجيل/دخول/خروج · كلمة مرور خاطئة · بريد غير موجود (رد موحّد)
- الجلسة المُبطلة مرفوضة فوراً · الجلسة المنتهية مرفوضة
- تغيير كلمة المرور يُبطل الجلسات الأخرى فقط
- رمز استعادة: مستخدم مرة واحدة · منتهٍ مرفوض
- Rate limit الدخول يعمل

### 2.8 Permissions & Tenancy

- مستخدم لا يصل معروض غيره → `NOT_FOUND` (لا 403 — منعاً للتعداد)
- مستخدم عادي على `/api/admin/*` → `FORBIDDEN`
- تعديل الدور من العميل لا يؤثر (الدور من DB)
- **عزل المستأجرين**: بيانات المنظمة A غير مرئية للمنظمة B في كل Repository

### 2.9 PDF / DOCX

- PDF يُنشأ ولا يكون فارغاً · حجم معقول
- **النص العربي في PDF قابل للاستخراج ومتصل** (لا حروف منفصلة) — يُفحص باستخراج النص ومقارنته
- DOCX: اتجاه RTL على الفقرات (`bidirectional`) ومحاذاة يمين
- كسر الصفحات لمعروض طويل
- إخلاء المسؤولية موجود في كلا الصيغتين

## 3. E2E — السيناريوهات

| # | السيناريو |
|---|---|
| E1 | **الرحلة الذهبية**: تسجيل → جهة → نوع → مقابلة → مراجعة → توليد → معاينة → تعديل → حفظ → PDF |
| E2 | **المنطق الشرطي**: «هل لديك مديونية؟ لا» ⇒ لا تظهر الأسئلة الفرعية · «نعم» ⇒ تظهر |
| E3 | **الاستئناف**: مغادرة في السؤال 4 والعودة ⇒ نفس الموضع والإجابات |
| E4 | **الحواجز**: رصيد صفر ⇒ رسالة ترقية · وصول معروض غير مملوك ⇒ 404 |
| E5 | **الإدارة**: إنشاء جهة + نوع + سؤال + شرط ⇒ يظهر فوراً في تدفّق المستخدم |
| E6 | **الجوال**: الرحلة كاملة على 375×812 |
| E7 | **A11y**: التنقل بلوحة المفاتيح عبر المقابلة كاملة + فحص محاور |

## 4. البيانات والتشغيل

```bash
npm run db:start          # PostgreSQL محلية
npm test                  # كل اختبارات Vitest
npm run test:unit
npm run test:integration  # يتطلب DATABASE_URL_TEST
npm run test:e2e
npm run verify            # typecheck + tests + build  ← بوابة كل مرحلة
```

- اختبارات التكامل تعمل على قاعدة `maroudak_test` تُعاد تهيئتها (`db push --force-reset`) قبل الحزمة.
- كل اختبار داخل معاملة تُلغى، أو ينظّف بياناته بـ `afterEach`.
- مزوّد AI وهمي (`FakeLLMProvider`) يُحقن عبر واجهة `LLMProvider` — **لا نداء شبكي في الاختبارات**.
- مولّدات بيانات في `tests/factories/` (مستخدم، جهة، سؤال، شرط، معروض).
